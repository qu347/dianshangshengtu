# 服装组图模块设计

- 日期：2026-08-28
- 状态：已确认，待实施
- 当前范围：模块二「服装组图」

## 1. 背景

项目当前已有「全品类商品图」模块。本轮新增独立的「服装组图」模块，用于根据服装参考图、指定模特和可选场景生成风格统一的电商图片组。

首版继续在本地运行，后续可能作为模块接入现有项目。因此服装业务保持独立边界，只复用已经稳定的上传、Grsai 调用、任务轮询、下载、平台语言和水印能力，不把两套业务流程混在同一组件中。

交互参考 [Picset 服装组图](https://picsetai.cn/zh-CN/clothing-studio) 以及用户提供的模特图、场景图生成弹窗截图，但最终行为以本文确认的规则为准。

## 2. 目标

用户能够完成以下闭环：

1. 上传 1–6 张服装参考图。
2. 上传或 AI 生成模特候选图，并选择一张作为整组唯一模特。
3. 可选地上传或 AI 生成场景候选图，并选择一张作为场景风格参考。
4. 设置平台、语言、图片比例、画质、水印和最终生成数量 1–16。
5. 由 AI 识别服装并生成数量准确、可编辑的中文出图规划。
6. 图一固定生成纯白背景的服装平铺商品图。
7. 图二及以后根据服装、模特、场景和规划生成一致的穿搭及细节图片。
8. 查看进度、重试单张失败结果，并下载单张或全部成功图片。

## 3. 非目标

首版不包含：

- 服装尺寸输入或尺寸标注图。
- 内衣、泳装等需要特殊合规与版型处理的品类。
- 用户账户、数据库、云端素材库或跨设备历史记录。
- 模特和场景候选的跨会话持久化。
- 支付、积分和生产环境部署。
- 为尚未确定的宿主项目提前设计通用工作流引擎。

## 4. 已确认的业务规则

### 4.1 支持的服装品类

首版支持：

- 上装。
- 下装。
- 连衣裙。
- 外套。
- 套装。

### 4.2 必需与可选素材

- 服装参考图必需，支持 1–6 张。
- 模特图必需，最终生成前必须选中一张。
- 场景图可选。
- 模特图和场景图都支持本地上传或 AI 生成候选图。
- AI 模特候选和场景候选每次可以生成 1–4 张。

### 4.3 最终图片数量

用户只选择最终数量 1–16，不手动勾选图片类型。AI 根据数量和服装特征规划每张图片。

- 数量为 1 时只生成固定白底平铺图。
- 数量大于 1 时，图二及以后由 AI 自动安排模特展示、场景图和细节图。

## 5. 技术与模块结构

采用独立模块方案：

- 页面入口：`/clothing-studio`。
- 前端功能目录：`features/clothing-studio`。
- 服务端接口命名空间：`/api/clothing/*`。
- 应用外壳中的「服装组图」导航变为可点击入口。

模块内部拥有独立的数据模型、页面状态、规划规则和生成编排，不直接复用商品图模块的业务组件。以下基础能力通过现有共享库复用：

- 图片上传、方向纠正、压缩和格式校验。
- Grsai Chat/视觉分析与 GPT Image 2 任务适配。
- 状态轮询、超时和单任务重试。
- 安全下载令牌、单图下载与 ZIP 下载。
- 平台、语言、比例、画质和水印配置。

不把现有商品图组件改造成多模式组件，避免服装规则影响已完成的商品图流程。

## 6. 页面设计

页面沿用当前项目的浅色专业工作台样式。

### 6.1 左侧素材与设置面板

左侧按顺序包含：

- 服装参考图上传区。
- 模特图选择卡片。
- 场景图选择卡片。
- 补充要求。
- 平台与目标语言。
- 图片比例与画质。
- 自定义水印。
- 最终生成数量 1–16。
- 「开始分析服装」主操作。

模特和场景卡片显示当前选择的缩略图，并提供「上传」「AI 生成」「重新选择」和「删除」。删除必选模特后不可开始分析；删除场景后流程恢复为无场景模式。

### 6.2 中间规划工作区

分析完成后展示可编辑的中文规划。每一项包含：

- 序号和图片类型。
- 标题。
- 画面目标。
- 场景与构图。
- 展示文案。
- 中文生图提示词。

图一的类型和核心规则固定，用户不能把它改成模特图或场景图；其他文本仍可在不破坏白底规则的前提下编辑。图二及以后可以修改规划文本。

### 6.3 生成结果区

结果区展示：

- 每张图片的排队、提交、生成、成功或失败状态。
- 成功图片预览、查看大图和下载。
- 失败原因和单张重试。
- 全部成功图片 ZIP 下载。

桌面端使用工作台多栏布局；窄屏下按素材、规划、结果顺序堆叠，模特和场景弹窗改为全屏布局。

## 7. 模特候选弹窗

弹窗采用双栏结构。

### 7.1 左栏生成设置

包含：

- 性别。
- 年龄段。
- 肤色或地域外观。
- 体型。
- 发型。
- 补充要求。
- 生成数量 1–4。

模特候选使用自然、有时尚感的姿势，同时强制以下可用性规则：

- 全身主体清晰，身体比例自然。
- 手臂不遮挡躯干和腰线。
- 头发不遮挡肩部与领口。
- 不穿外套，不使用遮挡身体的复杂配饰。
- 使用简单背景，便于后续服装替换和身份引用。

### 7.2 右栏候选来源

右栏可在「上传」和「AI 生成」之间切换，展示当前浏览器会话中的上传项及生成历史。用户选中一张后，通过底部固定的「使用选中的模特」返回主页面。

## 8. 场景候选弹窗

弹窗同样采用双栏结构。

### 8.1 左栏生成设置

包含：

- 风格。
- 场所。
- 光线氛围。
- 季节。
- 补充要求。
- 生成数量 1–4。

候选图的比例跟随最终组图设置。AI 场景图不包含人物、服装、商品、Logo 或可读文字，只提供空间、光线和视觉风格参考。

### 8.2 右栏候选来源

右栏可在「上传」和「AI 生成」之间切换。用户选中一张后，通过底部固定的「使用选中的场景」返回主页面。场景不是必需项，用户可以关闭弹窗并保持未选择状态。

## 9. AI 分析与规划规则

AI 先从服装参考图中提取：

- 服装类别。
- 颜色和配色。
- 版型和轮廓。
- 材质、纹理和工艺。
- 图案、Logo 和其他必须保持的识别特征。
- 正面、背面和局部细节的可观察信息。

不确定的信息必须明确标记，不得臆造面料成分、认证、功能或规格。

### 9.1 图一固定规则

图一始终是：

- 单件服装平铺展示。
- 纯白、无渐变、无纹理背景。
- 服装完整居中，不裁切，保留安全边距。
- 不出现人物、人体模型、衣架、场景道具、尺寸线或营销文字。
- 保持颜色、图案、Logo、结构和 SKU 特征与参考图一致。

图一只使用服装参考图，不使用选定模特和场景。

### 9.2 图二及以后规划

AI 根据数量与服装特点，从以下方向中选择最有价值的画面：

- 模特正面全身展示。
- 3/4 视角或自然动作展示。
- 侧面或背面版型展示。
- 穿搭及使用场景。
- 面料、做工、图案和卖点特写。

数量较少时优先覆盖白底商品、核心模特展示和最重要细节；数量增加时再扩展视角与场景，不生成无意义的重复构图。

### 9.3 一致性规则

- 所有需要人物的图片都引用同一张选定模特图。
- 脸部、体型、肤色和发型保持为同一人，只允许姿势、镜头和构图变化。
- 服装颜色、版型、图案、Logo、面料观感和关键结构保持一致。
- 选择场景后，整组沿用同一场景风格，但允许改变机位、景别和局部布置。
- 未选择场景时，AI 为图二及以后规划同一视觉体系下的简洁场景。

首版通过持续传入相同参考图和严格提示词约束一致性。生成模型仍可能出现小幅随机偏差；偏差明显的单图由用户使用原规划重试，不重新随机整套规划。

### 9.4 语言与水印

- AI 分析、规划和生图提示词使用中文。
- 图片中需要出现的文案根据平台自动使用中文、英文或俄文。
- 平台、语言和自定义水印规则完全复用全品类商品图模块的现有行为。

## 10. 两阶段生成流程

最终生成分为两个阶段。

### 10.1 阶段一：标准服装参考图

先只提交图一。图一成功后，服务端执行现有白底检查与近白背景归一化。

- 未满足纯白背景要求时自动重试一次。
- 第二次仍失败时显示明确错误，并允许用户手动重试。
- 图一失败期间不提交依赖它的后续图片。

### 10.2 阶段二：其余组图

图一成功后，图二及以后同时引用：

- 用户上传的原始服装参考图。
- 已生成并校验的图一。
- 选定模特图。
- 可选的场景图。
- 对应的已确认规划项。

客户端最多并发提交 3 张。单张失败不影响其他任务。图一重试成功后，尚未开始的后续任务自动继续。

重试保留原规划、模特、服装和场景引用，不重新分析，也不改变其他成功结果。

## 11. 服务端接口

### 11.1 `POST /api/clothing/model-candidates`

接收模特筛选条件与数量，返回规范化的候选生成任务。

### 11.2 `POST /api/clothing/scene-candidates`

接收场景筛选条件、比例与数量，返回规范化的候选生成任务。

### 11.3 `POST /api/clothing/analyze`

接收服装参考图、选定模特、可选场景和最终设置，返回服装分析及数量准确的中文组图规划。

结构化响应只允许执行一次受限格式修复；仍无效时返回可重试错误。

### 11.4 `POST /api/clothing/generate`

每次接收一个已确认规划项及对应受信素材引用。图一请求不接受模特和场景；图二及以后必须包含选定模特，并可包含场景。

### 11.5 任务查询与下载

服装模块使用独立的任务查询路由，但复用现有任务状态映射、安全下载令牌、远程图片读取和 ZIP 下载实现。浏览器不能把任意远程 URL 作为服装、模特、场景或图一引用提交给服务端。

## 12. 客户端状态

页面主状态为：

`input → analyzing → reviewing_plan → generating_main → generating_set → completed`

模特和场景候选弹窗各自维护：

- 当前筛选条件。
- 上传候选。
- AI 生成候选。
- 选中项。
- 独立任务状态。

候选历史仅存在于当前浏览器会话，不写数据库或长期素材库。刷新页面不恢复候选图库；仍在运行的最终生成任务可通过保存在会话存储中的任务编号继续查询。

## 13. 错误处理

- 上传失败：明确显示格式、大小、数量或解码错误，保留其他有效输入。
- 模特未选：阻止分析并定位到模特卡片。
- 候选生成失败：只影响对应候选，可原条件重试。
- 分析响应异常：保留全部输入，允许重新分析。
- 图一白底失败：停止后续任务并提供图一重试。
- 后续单图失败：其他任务继续，失败项单独重试。
- 查询超时：保留任务编号和「继续查询」入口，不自动重复提交以避免额外费用。
- 上游不可用、余额不足、审核失败和参数错误继续使用现有规范化错误信息。

## 14. 安全与隐私

- Grsai API Key 只存在于服务端环境变量。
- 图片必须通过现有 MIME、可解码性、尺寸和字节数检查。
- 受信图片引用继续使用短时签名令牌，拒绝客户端提供任意裸 URL。
- 服务端日志不记录 API Key、完整 Base64 图片或完整第三方响应。
- 模特、服装和场景图片不写入数据库。
- 下载与远程读取继续限制 HTTPS、DNS 解析、私网地址、响应类型、字节数和像素数。

## 15. 测试策略

自动化测试全部模拟 Grsai，不消耗真实额度。

### 15.1 单元测试

- 支持品类和表单校验。
- 模特必选、场景可选规则。
- 模特与场景筛选提示词。
- 图一固定平铺白底规划。
- 1–16 张规划数量和优先级。
- 平台语言与水印规则复用。
- 图二及以后的一致性提示词与素材引用。
- 图一依赖、最多 3 张并发和单项重试。

### 15.2 接口测试

- 模特候选和场景候选的 1–4 张数量限制。
- 分析结构化响应、一次格式修复和失败。
- 图一拒绝模特/场景依赖。
- 后续图片缺少模特、缺少有效图一令牌或使用非法 URL 时被拒绝。
- Grsai 立即成功、异步成功、审核失败、余额不足、网络异常和超时。

### 15.3 页面流程测试

覆盖：

`上传服装 → 生成并选择模特 → 可选场景 → 分析 → 修改规划 → 图一生成 → 后续并发生成 → 单项重试 → 下载`

另行覆盖上传模特、上传场景、无场景、最终数量为 1 和移动端弹窗流程。

### 15.4 真实冒烟测试

所有模拟测试通过后，真实测试只生成 1 张模特候选和一套 2 张最终图片，不测试 16 张批量任务。

## 16. 验收标准

- 「服装组图」导航可进入独立页面，且不影响全品类商品图。
- 用户可以上传 1–6 张支持品类的服装图。
- 模特可上传或 AI 生成并选择，未选择时不能开始最终分析。
- 场景可上传或 AI 生成并选择，也可以完全不选。
- 模特与场景每次可生成 1–4 张候选。
- 最终生成数量可选择 1–16，规划数量准确且可以编辑。
- 图一为完整、纯白背景、无人物的服装平铺图。
- 图二及以后引用同一模特，保持明显一致的身份、服装和场景风格。
- 最多同时生成 3 张，失败项可单独重试。
- 平台语言、比例、画质和水印行为与现有商品图模块一致。
- 单张和 ZIP 下载可用，API Key 不进入浏览器。
- 自动化测试不消耗 Grsai 额度，最小真实冒烟测试通过。
