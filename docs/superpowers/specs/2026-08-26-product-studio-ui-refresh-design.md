# 全品类商品图重试与 UI 优化设计

- 日期：2026-08-26
- 状态：已确认
- 范围：失败任务重试反馈、全品类商品图工作台视觉优化、上传预览紧凑化
- 参考：用户提供的浅色/深色双栏工作台截图；首版采用浅色方案

## 1. 目标

本轮在不改变现有业务闭环和 Grsai 接口的前提下，解决失败图片重试缺少反馈的问题，并将现有页面优化为更清晰、紧凑的桌面工作台。

验收结果包括：

1. 失败卡片的重试操作有即时、明确的状态反馈。
2. 页面采用浅色双栏工作台，视觉层级接近参考界面。
3. 上传后的产品图以约 96 像素缩略图显示，不再按原图尺寸占据左栏。
4. 桌面端保持输入与结果并列，窄屏下自然堆叠。
5. Figma 设计稿与本地页面使用同一布局和视觉规则。

## 2. 非目标

本轮不增加：

- 深色主题切换。
- 用户、积分、商城、历史任务或保存进度功能。
- 新的 Grsai 请求并发策略或后台任务队列。
- 「服装组图」业务页面。
- 与现有项目的组装和部署。

## 3. 重试问题与方案

### 3.1 已定位问题

真实生成中，单张图片曾因 Grsai 请求返回网络类 502 而失败；其他三张图片正常成功，因此该失败不是前端三分钟等待不足造成的。

当前页面使用全局生成锁保护生图操作。只要有生成操作仍在进行，所有失败卡片的重试按钮都会被禁用；禁用状态只有轻微透明度变化，且没有原因说明。若重试请求很快再次失败，卡片恢复到相同错误文本，用户也难以判断点击是否生效。

### 3.2 交互设计

- 保留单次生成操作锁，防止快速重复点击产生重复付费请求。
- 失败卡片可重试时显示主操作「重试此图」。
- 点击后立即把该任务切换为 `submitting`，显示「正在重新提交…」，并禁止重复点击。
- 如果页面中另一个生成操作尚未结束，按钮明确显示不可用原因「当前批次生成中，完成后可重试」。
- 重试成功后沿用现有 `submitting → running → succeeded` 状态。
- 重试失败后展示最新错误，并重新开放重试。
- 已成功任务不重新提交，查询超时任务仍使用「继续查询」，不新建生图任务。

## 4. 页面信息架构

### 4.1 应用外壳

- 浅灰页面背景、白色顶栏、细边框。
- 顶栏保留产品名称和「本地模式」状态，不仿制参考图中的积分、账户、消息或历史任务功能。
- 页面内容设置最大宽度并居中，减少宽屏下的视觉松散。

### 4.2 页面标题区

- 主标题为「商品视觉工作台」。
- 副标题说明从产品分析到批量生成的流程。
- 五步进度放在标题区下方，使用紧凑的数字、标题与状态样式，不再使用等宽的大色块。

### 4.3 双栏工作台

桌面端使用左窄右宽布局：

- 左栏约 360 像素，作为「项目配置」面板。
- 右栏占据剩余空间，作为「创作工作台」。
- 两栏使用白色卡片、圆角、细边框和轻阴影。
- 小于桌面断点时两栏依次堆叠。

## 5. 左栏设计

### 5.1 紧凑上传区

- 未上传时显示约 120 像素高的虚线拖放区，包含上传图标、提示和格式限制。
- 已上传图片显示为约 96 × 96 像素的缩略图网格。
- 每张缩略图包含删除按钮；文件名和大小使用单行省略显示。
- 继续上传入口与缩略图同级，不恢复成大图预览。
- 保持现有 1–6 张、格式、解码和大小校验逻辑。

### 5.2 输入和设置

- 产品名称、补充要求和生成设置分组显示。
- 标签、帮助文案、输入边框和间距统一。
- 「开始分析产品」作为左栏底部全宽主按钮。
- 现有平台、语言、比例和 1–16 生成数量范围不变。

## 6. 右栏设计

- 顶部固定显示「创作工作台」标题、当前阶段说明和阶段标签。
- 初始态提供清晰的空状态与下一步提示。
- 分析与规划阶段保留现有可编辑能力，但使用统一的分组标题、卡片和按钮样式。
- 生成阶段以两列结果网格为主；窄屏为一列。
- 成功卡片保留查看大图和下载；失败卡片使用醒目的错误状态和重试；超时卡片保留继续查询。
- 临时链接提示和「下载全部」位于结果区标题行，避免与单卡操作混淆。

## 7. 视觉规则

- 主背景：浅灰中性色。
- 面板：白色、细灰边框、轻阴影。
- 主文字：近黑；辅助文字：中性灰。
- 主按钮：近黑底白字；紫色只作为品牌点缀和当前步骤强调。
- 圆角保持克制，输入与按钮高度统一。
- 使用项目现有字体栈，不引入额外网络字体。
- 所有交互继续满足键盘操作、可见焦点和可访问名称要求。

## 8. Figma 交付

新建 Figma 设计文件「电商生图工作台 UI」，包含：

1. 「上传与分析」桌面画板。
2. 「生成结果」桌面画板，包含成功、失败和生成中状态。

先在 Figma 中建立浅色布局与关键组件，逐段截图检查；再以该稿作为本地实现依据。Figma 稿不添加非目标功能。

## 9. 测试与验收

自动化测试至少覆盖：

- 点击失败卡片后立即显示重新提交状态。
- 快速重复点击只产生一个提交请求。
- 页面忙碌时重试按钮给出明确原因。
- 重新提交失败后恢复可重试状态并展示最新错误。
- 上传预览使用紧凑缩略图结构，文件仍可删除和继续添加。
- 原有分析、规划、生成、继续查询、查看大图和下载测试保持通过。
