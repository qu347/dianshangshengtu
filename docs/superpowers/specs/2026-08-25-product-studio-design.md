# 全品类商品图模块设计

- 日期：2026-08-25
- 状态：已确认
- 当前范围：模块一「全品类商品图」

## 1. 背景

项目用于生成电商商品视觉，交互参考 [Picset](https://picsetai.cn/)。完整产品将来包含「全品类商品图」与「服装组图」两个模块，但本轮只实现前者；模块一验收后，再单独设计和实现模块二。

首版在本地运行，之后可能作为模块接入现有项目。当前设计只保留清晰的模块边界，不为尚未确定的集成方式增加抽象。

## 2. 目标

用户能够完成以下真实闭环：

1. 上传 1–6 张产品参考图。
2. 设置目标平台、语言、图片比例和生成数量 1–16。
3. 由视觉模型分析产品，提取可观察特征、目标人群、核心卖点与视觉方向。
4. 根据所选数量生成逐张出图规划。
5. 用户确认或修改每张图的主题、文案和提示词。
6. 使用 Grsai GPT Image 2 生成真实图片。
7. 查看每张图的任务状态，重试失败项，并下载单张或全部结果。

## 3. 非目标

首版不包含：

- 用户注册、登录和权限管理。
- 数据库、云端历史记录和跨设备恢复。
- 积分、套餐、支付和订单。
- 官网落地页及 Picset 的其他工具。
- 「服装组图」的业务流程。
- 面向生产环境的部署与现有项目集成。

页面刷新后，本次任务状态清空。

## 4. 技术方案

采用 Next.js App Router、TypeScript 和 Tailwind CSS，使用一个全栈应用同时承载界面与服务端 API。

选择该方案的原因：

- API Key 只存在于服务端。
- 本地只需启动一个服务。
- 页面、接口和 AI 适配器可以按功能边界组织。
- 后续可将功能模块接入现有 Next.js 项目，或保留接口契约迁移到其他宿主。

不采用纯前端直连，因为这会暴露 API Key；不采用独立 React 与 Express 双项目，因为首版没有需要承担额外部署复杂度的独立后端需求。

## 5. 模块边界

### 5.1 应用外壳

负责顶栏、模块导航和响应式布局。左侧导航包含：

- 全品类商品图：当前可用并高亮。
- 服装组图：保留入口，首版显示为后续模块，不实现业务功能。

### 5.2 全品类商品图功能

功能内包含以下职责单一的组件：

- 产品图上传与预处理。
- 生成参数表单。
- 商品分析结果展示。
- 可编辑出图规划。
- 批量生成队列。
- 生成结果与下载。

### 5.3 服务端 API

负责输入校验、调用 Grsai、规范化第三方错误和保护密钥。浏览器只调用本项目接口。

### 5.4 AI 适配层

统一封装：

- Grsai OpenAI 兼容 Chat API，用 Gemini 视觉模型分析商品。
- Grsai `gpt-image-2` 图片生成接口。
- Grsai 异步结果查询接口。

UI 不依赖 Grsai 的原始响应结构。

参考资料：

- [Grsai Chat API](https://grsai.ai/zh/dashboard/documents/chat)
- [Grsai GPT Image 2 新版接口](https://qmy27nhsd9.apifox.cn/452409160e0)
- [Grsai 异步结果查询接口](https://qmy27nhsd9.apifox.cn/452409577e0)

## 6. 页面布局

采用已确认的 A 方案：双栏工作台。

### 6.1 左栏

左栏始终显示任务输入：

- 1–6 张产品图上传区。
- 可选产品名称、已知卖点和补充要求。
- 目标平台。
- 目标语言。
- 图片比例。
- 生成数量，范围为 1–16。
- 「开始分析产品」主操作。

### 6.2 右栏

右栏随状态变化：

- 初始：操作说明和空状态。
- 分析中：明确的加载状态。
- 待确认：商品分析摘要和逐张出图规划。
- 生成中：逐张任务卡片与进度。
- 已完成：结果画廊、重试和下载操作。

桌面端左右并列；窄屏下模块导航转为顶部标签，左右栏依次堆叠。视觉使用浅色中性背景、白色内容面板、黑色高亮导航和克制的紫色步骤状态，与用户提供的导航截图保持一致。

## 7. 用户流程

### 7.1 输入

用户上传产品图并设置参数。图片在浏览器端完成方向纠正、尺寸压缩和格式规范化，再发送到服务端。

支持 JPG、PNG 和 WEBP。原始单文件上限为 15 MB。浏览器将图片方向纠正后，把最长边缩放到不超过 2048 像素，并以质量 0.9 的 WEBP 发送；规范化后的单文件仍超过 5 MB 时拒绝提交。上传阶段同时拒绝无法解码的文件和超过 6 张的输入。

### 7.2 AI 商品分析

服务端通过 Grsai Chat API 调用 Gemini 视觉模型。请求包含产品图片、用户已知信息、目标平台、语言和期望数量。

分析结果必须是结构化数据，至少包含：

- 商品品类和可观察外观特征。
- 材质与结构判断；不确定内容必须明确标记。
- 目标人群。
- 核心卖点。
- 建议的视觉与文案方向。
- 数量与用户选择完全一致的出图规划。

AI 不得臆造认证、功效、成分、规格或价格。用户明确提供的事实与模型从图片推断的内容分开保存。

### 7.3 规划确认

每个规划项包含：

- 图片序号。
- 类型，例如主图或详情图。
- 画面主题。
- 营销目标。
- 展示文案。
- 场景说明。
- 最终生图提示词。

用户可逐项修改，也可重新生成整套规划。如果用户修改产品图片或关键参数，现有规划标记为失效，必须重新分析。

### 7.4 图片生成

用户确认后，每个规划项独立调用 GPT Image 2。生成请求包含规范化产品参考图、该项提示词、图片比例和必要的产品一致性约束。

浏览器最多并发提交 3 个任务。每项独立经历：

`queued → submitting → running → succeeded | failed | timed_out`

单张失败不影响其他任务。失败项可以单独重试。

### 7.5 结果下载

成功图片以网格展示，支持：

- 查看大图。
- 单张下载。
- 全部成功图片打包为 ZIP 下载。

首版不持久化结果。Grsai 旧版文档将结果 URL 标记为两小时有效，因此首版一律按临时链接处理，并明确提示用户在当前会话内及时下载。

## 8. 服务端接口契约

### 8.1 `POST /api/product/analyze`

输入为多段表单：产品图片与生成参数。

输出为项目定义的商品分析与规划结构，不直接透传第三方响应。

服务端使用模式校验结构化结果。如果模型响应无法解析，则执行一次受限的格式修复；第二次仍失败时返回可重试错误。

### 8.2 `POST /api/product/generate`

输入为产品参考图、一个已确认规划项和生成设置。

输出为规范化任务：

- 本地规划项 ID。
- Grsai 任务 ID。
- 当前状态。

### 8.3 `GET /api/product/jobs/:id`

查询 Grsai 任务状态并映射为项目内部状态。成功时返回规范化结果 URL，以及由服务端签发、短时有效的下载令牌；失败时返回错误类别和可展示说明。

### 8.4 `GET /api/product/download`

代理下载已完成的结果。浏览器只提交 `/api/product/jobs/:id` 返回的下载令牌。服务端验证令牌签名、过期时间和其中的 HTTPS 结果 URL 后才执行下载，拒绝浏览器直接传入任意地址，避免成为通用网络代理。令牌使用服务端 `DOWNLOAD_TOKEN_SECRET` 签名。

## 9. 客户端状态

首版使用页面内状态，不使用数据库。状态分为：

- `input`
- `analyzing`
- `reviewing_plan`
- `submitting`
- `generating`
- `completed`

每张图有独立任务状态，批量状态由各子任务派生。页面刷新会清空任务，符合首版无历史记录的范围。

## 10. 异常处理

### 10.1 上传错误

在请求前显示具体问题：格式不支持、数量超限、图片损坏或文件过大。有效输入不因某一张失败而静默丢失。

### 10.2 分析错误

保留全部用户输入，展示可理解的错误并允许重试。结构化响应只自动修复一次，避免无限重试和额外消耗。

### 10.3 生成错误

统一映射：

- 内容审核失败。
- 参数错误。
- API Key 或权限错误。
- 积分或余额不足。
- 网络或上游服务异常。
- 查询超时。

仅失败项进入重试。重试不会重复提交已成功任务。

### 10.4 查询策略

任务查询采用退避轮询，并设置最长等待时间。超时后保留任务 ID，允许用户继续查询，而不是自动重新提交并产生重复费用。

## 11. 安全与隐私

- `GRSAI_API_KEY` 只存在于服务端环境变量，禁止使用 `NEXT_PUBLIC_` 前缀。
- `DOWNLOAD_TOKEN_SECRET` 只用于服务端签发短时下载令牌，同样禁止进入浏览器构建产物。
- 上传文件验证数量、MIME 类型、实际可解码性和大小。
- 服务端限制请求体积与第三方请求超时。
- 不在日志中记录 API Key、完整 Base64 图片或完整第三方响应。
- 向浏览器返回经过整理的错误，避免泄露请求头和内部堆栈。
- 下载代理只接受服务端签发的短时下载令牌，并验证签名、有效期和 HTTPS URL；拒绝用户提供的任意裸 URL。

## 12. 测试策略

自动化测试默认全部模拟 Grsai，不消耗积分。

### 12.1 单元测试

- 上传数量与格式校验。
- 分析结果模式校验与一次修复逻辑。
- 提示词拼装。
- 1–16 数量约束。
- 最多 3 个并发任务的队列。
- 任务状态映射、轮询退避和超时。
- 下载令牌签发、验签、过期和非法 URL 拒绝逻辑。

### 12.2 接口测试

使用模拟第三方响应覆盖：立即成功、异步进行中、成功、审核失败、余额不足、网络失败和超时。

### 12.3 页面流程测试

覆盖：

`上传 → 分析 → 修改规划 → 确认 → 生成 → 单项重试 → 下载`

### 12.4 真实冒烟测试

在所有模拟测试通过后，仅执行一次真实测试：上传 1 张产品图，分析并生成 1 张图片。不自动测试 16 张批量生成。

## 13. 验收标准

- 本地通过一条开发命令启动。
- 用户可以上传 1–6 张图片。
- 用户可以选择生成 1–16 张图片。
- AI 返回数量准确、可编辑的商品分析与出图规划。
- 用户确认后能调用 GPT Image 2 获得真实结果。
- 同时生成任务不超过 3 个。
- 单项失败可重试，不影响成功项。
- 成功图片支持单张与 ZIP 下载。
- 浏览器代码和构建产物不包含 API Key。
- 自动化测试不消耗 Grsai 积分。
- 一次单图真实冒烟测试通过。

## 14. 后续模块

模块一验收后，再为「服装组图」单独完成需求梳理、设计和实施计划。它可以复用应用外壳、上传预处理、任务状态、结果下载和 Grsai 适配层，但不会提前把服装业务塞入模块一。
