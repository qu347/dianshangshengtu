# 智能立体尺寸图设计

日期：2026-08-27

## 目标

修复前两张固定图片的质量问题：图一稳定输出完整的纯白底商品主图；图二先由 GPT Image 2 基于图一生成纯白背景的 3/4 立体商品图，再由视觉 AI 判断商品边界和尺寸标注方向，最后由服务端绘制准确的黑色尺寸线与文字。

最终尺寸值只能来自用户输入。AI 不得生成、修改或推断尺寸值。

## 非目标

- 不让图片模型直接绘制尺寸文字或尺寸线。
- 不引入数据库、对象存储或后台队列。
- 不改变第三张及后续图片的现有生成逻辑。
- 不修改现有平台语言、单位换算和水印规则。

## 根因

1. 当前图一校验只接受背景带中精确的 `RGB(255,255,255)` 像素。图片模型常输出肉眼为白色但带压缩、渐变或轻微灰度的背景，因此结果被判失败。
2. 当前图二要求模型把商品放在左侧 65%，服务端又在右侧覆盖宽 35%、透明度 78% 的白色标注面板。这一覆盖层直接造成左右背景色差和拼接感。
3. 当前尺寸标注只是一组右侧水平引导线，没有利用商品实际轮廓，也无法表达宽、高、口径、容量等不同尺寸语义。

## 用户可见行为

### 图一：纯白底商品主图

- 商品结构、颜色、材质、Logo 和 SKU 与参考图一致。
- 商品完整、居中、不裁切，四周保留安全边距。
- 提示词明确要求整张画布为无渐变、无纹理的白色背景；允许商品主体附近存在自然接触阴影，但画布边缘必须可归一化为纯白。
- 服务端把与画布边缘连通的近白色背景归一化成精确白色。若背景不是可安全识别的近白色区域，则图一失败并显示现有“重试此图”入口。

### 图二：智能立体尺寸图

- 图二必须等待图一成功。
- 服务端验证图一的签名下载令牌，通过现有安全远程图片读取器取得图一结果，完成白底归一化后转为内存中的 PNG data URL；该图一连同用户原始参考图作为 GPT Image 2 的参考图。
- GPT Image 2 生成一个纯白背景、商品完整居中、保留足够标注边距的 3/4 立体视角底图；图片模型不得生成任何文字、数字、单位、尺寸线或装饰面板。
- 图二底图生成成功后，服务端通过同一安全读取器取得并归一化底图，再以内存 PNG data URL 交给视觉 AI。视觉 AI 只返回商品归一化边界框和每个尺寸的标注方向/侧边，不得返回尺寸值。
- 服务端把 AI 返回的稳定尺寸 ID 与用户尺寸逐项绑定。ID 缺失、重复、乱序或数量不一致时，不采用部分结果，直接使用确定性回退排版。
- 服务端在归一化后的整张白色底图上绘制黑色尺寸线、端点、标签和值，不再绘制右侧白色覆盖面板。

## 智能标注数据

视觉 AI 返回严格 JSON：

```json
{
  "bounds": { "left": 180, "top": 260, "right": 820, "bottom": 790 },
  "placements": [
    { "id": "dimension-id", "axis": "horizontal", "side": "top" }
  ]
}
```

- 坐标使用 `0..1000` 的归一化整数，与实际输出分辨率无关。
- `axis` 只能是 `horizontal`、`vertical` 或 `callout`。
- `side` 只能是 `top`、`right`、`bottom` 或 `left`。
- AI 只接收稳定尺寸 ID 和标签，不接收可改写的尺寸值。
- 服务端验证边界框面积、坐标顺序、安全边距、ID 完整性和枚举值。
- AI 结果无效时采用回退：第一个尺寸为上方横线，第二个为右侧竖线，第三个为下方横线，第四个为左侧竖线，其余使用左右空白区域的黑色引导线。

## 白底归一化

服务端解码图片并从四条画布边缘执行连通区域扫描：

- 仅把亮度足够高且 RGB 通道差足够小的近白色像素视为背景候选。
- 只有与画布边缘连通的候选像素会被改成 `RGB(255,255,255)`；商品内部不连通的高光不会被处理。
- 归一化后重新检查外围背景带。外围背景不满足白底比例时拒绝结果。
- 图一和图二下载/预览都经过同一归一化函数，保证预览和下载字节一致。

## 标注绘制

- 线条、端点和文字统一使用黑色；不使用半透明侧栏或不同颜色的背景块。
- 横向尺寸线与 AI 商品边界的左右边缘对齐，放在指定的上方或下方。
- 纵向尺寸线与商品边界的上下边缘对齐，放在指定的左侧或右侧。
- `callout` 使用折线从商品边缘指向最近的空白区域。
- 多个同侧标注按固定间距向外错开，避免重叠；文字必须限制在安全区内。
- 标签使用目标平台语言，值使用现有可信单位换算结果。
- 水印在尺寸标注之后绘制，并继续遵守现有规则：Amazon 图一无水印、其余应加水印的图片保持不变。

## 生成与重试流程

1. 客户端先提交图一；第三张及后续图片可以继续使用现有并发逻辑。
2. 图一成功后，客户端把图一下载令牌作为受信引用提交图二。
3. 服务端验证令牌、读取图一源图，再提交图二立体底图任务。
4. 图二立即成功或轮询成功时，服务端执行视觉锚点分析；分析异常时使用回退排版，而不是让图二失败。
5. 服务端把图二源 URL、可信标注、边界框、排版结果和水印配置签入现有下载令牌。
6. 图一失败时图二进入失败状态并提示先重试图一；图一重试成功后可以单独重试图二。

图二的额外视觉分析最多调用两次：首次严格 JSON 请求和一次格式修复。不会无限重试。

## 安全与一致性

- 客户端不能提交任意远程图片 URL，只能提交服务端签发且未过期的图一下载令牌。
- 图一源图继续通过现有 HTTPS、DNS 固定、私网地址拒绝、MIME、字节数和像素限制。
- 下载令牌验证新增的边界框和标注排版字段，拒绝超限坐标、未知枚举或不完整数据。
- 预览、单图下载和 ZIP 下载继续调用同一个服务端渲染入口，输出相同的 PNG 字节。

## 错误处理

- 图一背景无法安全归一化：显示“白底商品主图背景处理失败，请重试此图”。
- 图二缺少有效图一令牌：显示“请先生成或重试白底商品主图”。
- 图二立体底图生成失败：保留现有单图重试。
- AI 锚点分析失败：静默使用确定性回退排版，并正常返回图二。
- 渲染配置或下载令牌无效：保持当前通用下载失败响应，不暴露服务商或签名细节。

## 测试与验收

- 提示词测试：图一纯白完整商品；图二 3/4 立体视角、纯白背景、无文字和标注。
- 白底测试：近白连通背景被转为纯白；非白背景被拒绝；灰色商品和内部高光不被错误抹除。
- 流程测试：图二等待图一；使用图一令牌；图一失败时图二不提交；图一成功后图二可重试。
- AI 锚点测试：有效边界和稳定 ID 被接受；乱序、重复、缺失、越界结果触发回退；AI 无法修改用户尺寸值。
- 渲染测试：整张背景一致，不存在右侧 35% 色差；首个横向标注在商品上方，第二个纵向标注在商品右侧；黑色线条和文字存在；最多六个标注不越界。
- 令牌测试：新增排版字段可签发/验证，篡改和超限字段被拒绝。
- 端到端测试：全程拦截 Grsai 请求，覆盖图一成功、图二立体生成、锚点分析、预览和下载，不调用真实服务。

## 成功标准

- 图一不再因轻微灰白背景被误判，同时最终输出的画布背景为纯白。
- 图二为完整的 3/4 立体商品图，商品不裁切，整张背景一致为白色。
- 图二不再出现右侧三分之一背景色差。
- 标注线和文字为黑色，并围绕商品轮廓显示。
- 所有尺寸标签和数值与用户输入、平台语言及单位换算一致。
- 图二 AI 锚点失败时仍能输出可用的确定性标注图。
